# Активация плагина в OpenVidu Meet

В [roadmap #21](https://github.com/dwspurpleteam/roadmap/issues/21) плагин запускается на звонок. Модератор выбирает опубликованную версию в панели Plugins. Meet показывает состояние активации и открывает UI плагина в своём layout после `ACTIVE`. Участники видят одно состояние активации, а размещение окна каждый меняет у себя.

## Настройка

| Переменная backend Meet            | Назначение                                                                                                                  |
| ---------------------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| `MEET_PLUGIN_MANAGER_URL`          | Внутренний HTTP(S) origin Plugin Manager, например `http://pluginmanager:8080`. Включает активацию опубликованных плагинов. |
| `MEET_PLUGIN_ACTIVATION_MOCK=true` | Добавляет отдельный плагин **Plugin activation demo** на сервере Meet, включая production-сборку. По умолчанию выключен.    |

В режиме Manager входящие запросы браузера идут через Meet Backend с токеном участника. Маршруты Manager для записи следует делать доступными только доверенным сервисам. Публичные маршруты Registry `GET /v1/plugins` и `GET /v1/plugins/{pluginId}/versions` должны быть доступны на origin Meet. [Каталог](plugin-ui-integration.md), [OpenAPI Meet](../meet-ce/backend/openapi/plugins/plugin-activations.yaml).

### Демонстрация на сервере

Разверни образ Meet с этой реализацией и добавь флаг в окружение контейнера. В конфигурации Vareonix окружение Meet задаётся в `deployer/apps/calls/meet/vars/base.yaml` под `app.env`.

```yaml
app:
    env:
        MEET_PLUGIN_ACTIVATION_MOCK: 'true'
```

Если требуется запуск опубликованных плагинов, укажи также `MEET_PLUGIN_MANAGER_URL: http://pluginmanager:8080`. При обоих параметрах демо и настоящие плагины доступны одновременно. При сбое чтения статусов из Manager панель показывает ошибку синхронизации, а демо продолжает работать. Если задан только флаг демо, опубликованные записи остаются видны в каталоге и доступны для просмотра. Для выключения демо убери флаг и перезапусти Meet.

### Проверка демо

Для локальной проверки тот же флаг можно передать обычному dev-окружению Meet с LiveKit и Redis.

```bash
MEET_PLUGIN_ACTIVATION_MOCK=true ./meet.sh dev
```

1. Войди в звонок как модератор и открой Plugins → **Plugin activation demo** → **Activate**. Демонстрационная запись доступна и при недоступном Registry.
2. После `Activating…` появится `Active` и iframe **Demo plugin is active**. Сервер имитирует готовность через секунду, клиенты опрашивают состояние раз в пять секунд.
3. Войди вторым участником в тот же звонок. После запроса состояния он увидит то же окно. У участника без роли модератора кнопка запуска недоступна.
4. Перемести окно, сверни и восстанови его. Выход из звонка очищает окно и его локальное размещение. В новом звонке той же комнаты активация предыдущего звонка не отображается.

Демо использует тот же внутренний API, авторизацию, Redis и layout, что и режим Manager. Mock состоит из встроенной записи `meet-activation-demo`, перехода `ACTIVATING → ACTIVE` по таймеру и статического iframe с полным sandbox. Данные и статусы опубликованных плагинов поступают из реальных сервисов. Демо подтверждает работу кнопки, общего состояния звонка и iframe.

## Какие контракты использует Meet

- **Браузер → Meet Backend.** `GET /internal-api/v1/rooms/{roomId}/plugin-activations?callId=…` возвращает состояние активаций для участников. `POST` на тот же ресурс принимает `callId`, `pluginId` и `pluginVersion`, возвращает `202` и состояние активации. Оба запроса требуют токен участника комнаты с правом входа, действующего участника LiveKit и текущий `Room.sid` при включённой активации. `POST` требует роль модератора. Переданный `callId` проверяется сервером. `roomId` соответствует имени комнаты LiveKit, `callId` различает звонки в этой комнате.
- **Meet Backend → Plugin Manager.** Читает версионную конфигурацию `GET /v1/plugins/{pluginId}/versions/{version}/configuration` и закрепляет возвращённый `registryId`. Отправляет `POST /v1/activations` с явной версией, серверным `requestedBy` и частичным `initialContext`. В снимок входят идентификаторы участников, роли и время входа. Имена, пользовательские метаданные и токены не передаются. Состояние читается по `GET /v1/activations/{activationId}`.
- **Состояние звонка в Meet.** Пока у Manager нет выдачи списка по звонку, Meet хранит в Redis свой индекс активаций по `Room.sid` с TTL 32 дня. Регистрируется одна нетерминальная активация плагина на звонок. До вызова Manager индекс сохраняет точный запрос и `idempotencyKey`. При сетевой ошибке повтор с той же версией отправляет тот же запрос, а после подтверждения в Redis остаются ID активации и данные для UI. После `FAILED` или `STOPPED` запуск создаёт новую активацию. Активации, созданные напрямую в Manager, в индекс не попадают.
- **Meet → iframe.** Meet использует адрес из зафиксированной конфигурации после `ACTIVE`. Внешний адрес должен быть абсолютным HTTPS URL без credentials и с origin, отличным от Meet и документа, где выполняется UI. Плагину нужно разрешить встраивание через `frame-ancestors`, а CSP документа Meet или встраивающего приложения должна разрешать его через `frame-src`, если такая директива задана. Без пригодного адреса панель показывает статус и недоступность окна. Подписанный launch context и обмен сообщениями с дочерним iframe пока не подключены. [Оконная механика](floating-windows-and-plugin-integration.md).

## Как перейти на обновлённые сервисы

| Что проверить после обновления                                                                                                                                                                                                                                | Где менять Meet                                                                                                                                                                                                                                                                          |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Registry публикует подходящий манифест, Manager принимает его, backend плагина отвечает на `POST /platform/control` и с выданными данными открывает подписку в streamapi. Выбрать в панели точную версию и проверить `ACTIVATING → ACTIVE` в тестовом звонке. | Если изменилась форма Manager, обновить схемы и HTTP-вызовы в `meet-ce/backend/src/services/plugin-activation.service.ts`. Если поменялись страницы версий, обновить `listVersions` в `plugin-catalog.service.ts`.                                                                       |
| Manager предоставит список активаций по `callId`, уведомление об изменениях и поддерживаемую остановку.                                                                                                                                                       | Подключить список к `PluginActivationService.list` и убрать временный индекс зарегистрированных активаций после миграции. Сохранить повторяемость регистрации с тем же снимком. Уведомления смогут заменить опрос, а остановку нужно проводить через серверный маршрут с проверкой прав. |
| Frontend SDK и спецификация согласуют `Room.sid`/имя комнаты, подписанный контекст и проверку origin и окна.                                                                                                                                                  | Добавить протокол дочерних iframe у `PluginIframeWindowComponent`. Проверять точный origin, `event.source` и привязку к активации. Существующий bridge в `domains/embedded` обслуживает родительскую страницу Meet.                                                                      |
| На тестовом окружении проверен запуск, выдача статуса всем участникам, подписка на события звонка и открытие iframe.                                                                                                                                          | Снять `MEET_PLUGIN_ACTIVATION_MOCK`. Затем удалить `mockPlugin`, ветки `mock` и обработку `managerStatusUnavailable` в обоих сервисах активации и OpenAPI, demo-строку в панели и ветку `srcdoc` в компоненте окна. У ключей `ov_meet:plugin_activations:mock:*` свои префикс и TTL.     |

На 2026-11-18 на `calls.vareonix.cc` опубликована `attendance@0.1.0`. Её конфигурация читается по явной версии. У закреплённой сборки нет lifecycle-обработчика, указанного в манифесте, и её UI раздаётся с origin Meet. В актуальном Manager PR #6 код читает `backend.control-url`, но проверка версии ещё требует `0.1`. Registry PR #9 принимает `1.1`. Для сквозной проверки нужен совместимый набор сборок и отдельный origin для iframe. [Manager PR #6](https://github.com/dwspurpleteam/plugin-manager-service/pull/6), [Registry PR #9](https://github.com/dwspurpleteam/plugin-registry/pull/9), [Attendance](https://github.com/dwspurpleteam/plugins/tree/099aeb2258a01de7942eaaddaf645d60c68fa8f9/plugin-attendance), [Specs PR #6](https://github.com/dwspurpleteam/specs/pull/6).

Успешное получение конфигурации и загрузка страницы плагина сами по себе не проверяют запуск backend или подписку на события. Приёмка должна включать изменение состава тестового звонка и подтверждение, что его получил активированный backend плагина.
