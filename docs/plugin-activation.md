# Активация плагина в OpenVidu Meet

Модератор выбирает опубликованную версию в панели **Plugins**, проверяет запрашиваемые разрешения и нажимает **Activate**. Meet показывает участникам состояние активации и открывает окно плагина после `ACTIVE`. Каждый участник управляет размещением своего окна.

## Настройка

Задайте `MEET_PLUGIN_MANAGER_URL` в окружении сервера Meet. Используйте внутренний HTTP(S)-адрес сервиса управления плагинами (Plugin Manager). В рабочем окружении Vareonix сервис называется `pluginmanager` и слушает порт `8080`. При развёртывании образа Meet с поддержкой активаций добавьте адрес в `app.env`. [Конфигурация Meet в Vareonix](https://github.com/dwspurpleteam/deployer/blob/main/apps/calls/meet/vars/base.yaml).

```yaml
app:
    env:
        MEET_PLUGIN_MANAGER_URL: http://pluginmanager:8080
```

Удалите из окружения прежний флаг `MEET_PLUGIN_ACTIVATION_MOCK`. Если адрес сервиса управления плагинами не задан, каталог остаётся доступен, а кнопка активации выключена. Для локальной разработки можно запустить `./meet.sh dev` с адресом сервиса и рабочими LiveKit и Redis.

Браузер обращается к маршрутам реестра `GET /v1/plugins`, `GET /v1/plugins/{pluginId}/versions` и `GET /v1/plugins/{pluginId}/versions/{version}/manifest` по адресу сервера Meet. Запрос на активацию отправляет сервер Meet. Доступ к маршрутам записи сервиса управления плагинами следует ограничить доверенными сервисами. [Каталог](plugin-ui-integration.md), [OpenAPI Meet](../meet-ce/backend/openapi/plugins/plugin-activations.yaml).

## Сквозная проверка плагина посещаемости

На `calls.vareonix.cc` опубликована версия плагина посещаемости `attendance@1.0.1` из реестра `local` с манифестом 1.1. Сервис управления плагинами отправляет сообщение по адресу `backend.control-url`. Плагин подписывается на события StreamAPI перед подтверждением запуска. [Манифест](https://calls.vareonix.cc/v1/plugins/attendance/versions/1.0.1/configuration), [Изменения в сервисе управления плагинами](https://github.com/dwspurpleteam/plugin-manager-service/pull/6), [Изменения в плагине посещаемости](https://github.com/dwspurpleteam/plugins/pull/4).

1. В новом тестовом звонке войдите как модератор и выберите **Plugins → Плагин посещаемости → 1.0.1**. Проверьте, что панель показывает события входа и выхода участников и завершения звонка. Нажмите **Activate**.
2. Дождитесь статуса **Active** и окна «Посещаемость». В запросе страницы плагина будет `?callId=RM_…` с SID текущего звонка. Если запуск завершился с `FAILED`, код ошибки отображается рядом со статусом.
3. Войдите вторым участником после появления **Active**. У обоих должно появиться окно, а новый участник должен попасть в список присутствующих. После выхода второго участника проверьте список покинувших звонок. Плагин учитывает события с момента запуска подписки.
4. Сверните и восстановите окно, затем завершите звонок и войдите в ту же комнату заново. Окно должно появиться в новом звонке после отдельной активации.

Для диагностики используйте API сервиса управления плагинами в отдельном тестовом звонке. Отправьте `POST /v1/activations` с SID звонка в `callId`, `pluginId: "attendance"`, `pluginVersion: "1.0.1"`, `pluginRegistryId: "local"`, `requestedBy` и уникальным `idempotencyKey`. Проверьте `state: "ACTIVE"` через `GET /v1/activations/{activationId}` и откройте `https://calls.vareonix.cc/apps/plugin-attendance/?callId=RM_…`. Meet хранит в своём индексе только активации, созданные из панели. [Контракт API](https://github.com/dwspurpleteam/plugin-manager-service/blob/73f132fbd28a0cef8cd7660501c0582490e9a7fb/docs/openapi/openapi.yaml).

## Контракты Meet

- **Браузер → сервер Meet.** `GET /internal-api/v1/rooms/{roomId}/plugin-activations?callId=…` возвращает состояние активаций. `POST` принимает `callId`, `pluginId` и `pluginVersion`, возвращает `202` и состояние активации. Для активаций нужен токен участника с правом входа и действующая сессия LiveKit. Для `POST` нужна роль модератора. Сервер сверяет `callId` с текущим `Room.sid`. Параметр `roomId` соответствует имени комнаты.
- **Сервер Meet → сервис управления плагинами.** Meet читает `GET /v1/plugins/{pluginId}/versions/{version}/configuration` и закрепляет возвращённый `registryId`. В `POST /v1/activations` отправляются явная версия, серверный `requestedBy` и частичный `initialContext` с идентификаторами участников, ролями и временем входа. Состояние читается через `GET /v1/activations/{activationId}`. Панель опрашивает Meet раз в пять секунд и показывает ошибку синхронизации при недоступности статусов.
- **Индекс состояния.** Meet хранит в Redis активации, созданные из панели, с ключом по `Room.sid` и TTL 32 дня. Для одного плагина в звонке допускается одна нетерминальная активация. При сетевой ошибке повтор с той же версией отправляет сохранённый запрос с тем же `idempotencyKey`. После `FAILED` или `STOPPED` запуск создаёт новую активацию.
- **Meet → iframe.** После `ACTIVE` Meet берёт `frontend.url-web` из зафиксированной конфигурации и добавляет или заменяет параметр `callId`. Адрес должен быть абсолютным HTTPS URL без логина и пароля. Браузер присваивает iframe с `sandbox="allow-scripts"` непрозрачный источник, даже если плагин и Meet находятся на одном сервере. Сервер плагина должен разрешить загрузку клиентских ресурсов и запросы API с `Origin: null` через CORS. Плагин посещаемости обращается к своему API без cookie, поэтому по адресу из манифеста должны быть доступны интерфейс и API того же окружения. Заголовки встраивания плагина и CSP страницы Meet должны разрешать iframe. [Оконная механика](floating-windows-and-plugin-integration.md).
