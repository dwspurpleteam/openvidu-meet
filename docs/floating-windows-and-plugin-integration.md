# Плавающие окна и контейнеры плагинов

Оконная механика используется для медиаплиток и iframe активированных плагинов. Настройка сервиса управления плагинами, проверка плагина посещаемости и серверный контракт описаны в [инструкции по активации](plugin-activation.md).

## Что работает сейчас

Камера, аватар, демонстрация экрана и iframe плагина используют общую оболочку `WindowShellComponent` через композицию. `MeetingCustomLayoutComponent` подаёт в Smart Layout окна активированных плагинов. Видимый iframe замещает экран ожидания или приглашения для участника, который находится в звонке один.

Общая механика поддерживает:

- Открепление из сетки и возврат в неё без второй копии плитки.
- Перемещение за заголовок и независимое изменение ширины и высоты за любой из четырёх углов.
- Сворачивание кнопкой или перетаскиванием в правый док и восстановление прежней геометрии в текущих границах.
- Перемещение и изменение размера стрелками, увеличенный шаг с Shift и отмену изменения размера указателем.
- Один DOM-элемент содержимого для окна в сетке, плавающего и свёрнутого окна. При переходах iframe сохраняется.
- Отдельный учёт откреплённых камер в Smart Mosaic и заполнение освободившихся ячеек сетки.
- Единственный контейнер звука удалённых участников. При сворачивании окна звук продолжает воспроизводиться, камера продолжает публиковать видео.

### Правила размещения окон

Размещение, геометрия и док действуют для конкретного участника и сбрасываются при перезагрузке страницы или смене звонка. Настройка плавающего окна собственной камеры сохраняется отдельно в браузере.

Начальный размер плавающего окна — 320 × 220, обычный минимум — 160 × 100. Если рабочая область меньше, размер ограничивается её границами. Ширину и высоту можно менять независимо. Рабочая область занимает сетку звонка над панелью субтитров.

При появлении удалённого участника окно собственной камеры может стать плавающим. Когда уходит последний удалённый участник, окно возвращается в сетку. Вручную свёрнутая камера автоматически не разворачивается. Закрепление вручную возвращает медиаплитку в сетку. При автоматическом закреплении демонстрации экрана откреплённое или свёрнутое окно сохраняет своё положение.

Состояние `minimized` относится только к размещению окна. Жизненный цикл плагина и ограничения на число активаций относятся к серверной части.

## Контракт оконной механики

Окна проходят через следующие компоненты.

```text
PluginActivationService.windows → PluginWindow[]
  → SmartLayoutComponent.pluginWindows
  → BaseLayoutComponent.pluginWindows
  → WindowShellComponent + PluginIframeWindowComponent
```

`PluginWindow` содержит ID, заголовок и URL iframe с `callId`. ID окна имеет вид `plugin:<activationId>`. При опросе тот же ID сохраняет DOM и геометрию. Iframe не создаёт LiveKit-участника и не публикует RTC-поток.

`StreamLayoutStateService` хранит локальное размещение отдельно от описаний окон.

```text
windowPlacement(id) → { mode: 'grid' | 'floating' | 'minimized', rect? }
setWindowMode(id, mode)
setWindowRect(id, rect)
clearWindow(id)
clearAllViewState()
```

Отсутствующая запись означает `grid`. `isStreamFloating(id)` включает `minimized`. Когда окно исчезает из состояния звонка, сервис активации убирает его из раскладки и вызывает `clearWindow(id)` для очистки локального размещения. Остановка плагина требует отдельного вызова сервиса управления плагинами.

## Перед открытием внешнего iframe

Meet проверяет URL на сервере и в клиенте перед передачей Angular. Интерфейс открывается по HTTPS в iframe с `sandbox="allow-scripts"`. Браузер присваивает ему непрозрачный источник и запрещает доступ к камере, микрофону, захвату экрана и геолокации. Для модульных скриптов и запросов API плагин должен поддерживать CORS для `Origin: null`. Встраивание также зависит от заголовков ответа плагина и CSP страницы, которая его встраивает.

Подписанный контекст и обмен сообщениями с iframe плагина остаются следующим этапом. Обработчик должен проверять готовность SDK, версию и размер сообщения, точные `event.origin`, `event.source === iframe.contentWindow` и привязку к активации. [Архитектура сервиса плагинов](https://github.com/dwspurpleteam/specs/blob/main/specs/plugin-service-architecture/spec.md).

## Инварианты при дальнейших изменениях

- Использовать один экземпляр Smart Layout, чтобы сохранить общий сервис раскладки и единственный контейнер звука.
- Сохранять один iframe под тем же родительским DOM-элементом. При переходах между сеткой, плавающим и свёрнутым режимами менять размещение и CSS этого элемента, сохраняя `track plugin.id`.
- Сохранять стабильный ID камеры при выключении видео и отдельный ID демонстрации экрана. Откреплённые камеры должны отображаться независимо от выбора плиток для сетки. Видео в видимых плавающих окнах должно продолжать воспроизводиться.
- Исключать док и защитные слои из расчёта сетки через `OV_floating` и `OV_ignored`. Во время перетаскивания и изменения размера нужна защита при пересечении любого iframe.
- Поддерживать Shadow DOM, не переносить окна в `document.body`.
- Хранить локальное размещение отдельно от состояния активации. Сохранять геометрию при обновлении статусов.

## Проверки

Модульные тесты `window-shell.component.spec.ts`, `base-layout.component.spec.ts`, `smart-layout.component.spec.ts` и `stream-layout-state.service.spec.ts` проверяют сохранение iframe, геометрию, перетаскивание в док, Smart Mosaic, звук и очистку состояния. В этих тестах используются тестовые описания iframe.

`meet-ce/frontend/e2e/windows.test.ts` проверяет каталог с подменённым HTTP-ответом, открепление плиток удалённых участников и демонстрации экрана, а также отсутствие дублирования звука. Для сквозных тестов нужны работающие Meet, LiveKit и хранилища. [Сквозная проверка плагина посещаемости](plugin-activation.md#сквозная-проверка-плагина-посещаемости).
